# Классификация твитов о катастрофах с помощью Gemma-2-2B и Unsloth

В этом проекте выполнено дообучение модели **Gemma-2-2B** в режиме `SequenceClassification` с использованием фреймворка **Unsloth** на данных соревнования Kaggle [**Natural Language Processing with Disaster Tweets**](https://www.kaggle.com/competitions/nlp-getting-started/overview "Перейти на страницу конкурса").

## Результаты
- **Результат на Kaggle: F1-score = 0.84339** на тестовом наборе данных / Public Leaderboard.
- **Сбалансированная валидация:** оптимизированный порог классификации **0.51, Macro F1-score ~ 0.83**.
- **Эффективность GPU:** полный цикл дообучения на одной облачной видеокарте **NVIDIA Tesla T4** занимает около 20 минут.

---

## Основные моменты в пайплайне

### Конкатенация разнородных текстовых признаков
Табличные метаданные `keyword` и `location` обработаны на уровне Pandas с заменой пропусков `NaN` на текстовый маркер `"unknown"` и объединены в единый структурированный текст с помощью разделителей:
```text
"Keyword: {keyword} | Location: {location} | Text: {text}"
```
Это позволило механизму внимания модели учитывать географический и тематический контекст твита.


### Настройка гиперпараметров
- **Максимальная длина последовательности:** 256 токенов
- **Размер батча:** 16 (с `gradient_accumulation_steps = 2`, эффективный батч = 32)
- **Прогрев скорости обучения:** `warmup_steps = 100`
- **Скорость обучения:** `8e-5` с расписанием `cosine`
- **Оптимизатор:** `paged_adamw_8bit`

> *На момент запуска базовые сиды были зафиксированы через `set_seed()`, однако переменные окружения для детерминизма CUDA не были прописаны.*
> 
> *Из-за этого веса LoRA-адаптеров в разных сессиях шли к оптимуму по несколько различающимся математическим траекториям. Тем не менее, благодаря корректной стратификации выборки и подбору порогов, общая разделяющая способность модели и её итоговый скор на валидации остаются достаточно высокими при любом перезапуске, но могут незначительно отличаться.*
